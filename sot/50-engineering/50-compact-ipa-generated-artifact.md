# SOT-ENG-050: IPA 辞書の同等な生成表現

- 状態: 廃止
- 廃止理由: SDK の権利表示と patch 識別情報を公式 archive に追加し、配布物全体の閉じた構成を独立した SDK 成果物規定へ移すため。
- 後継: [SOT-ENG-051](51-compact-ipa-generated-artifact-v2.md)

## 規定

検索語前処理で使用する IPA 辞書は、固定した上流成果物から再現可能に生成し、語彙、分割結果および製品が公開する全ての token 情報を保持した表現だけを採用する。生成元、変換、生成物および必要な権利表示を一つの検証可能な成果物集合として管理する。

## 適用境界

本規定は `internal/nlp/kagome` が使用するシステム辞書の保存・読込み表現を対象とする。法令名辞書、法概念辞書、登録語、検索結果の意味、tokenizer の分割規則および公開機能の範囲を変更しない。

固定版の語 ID、形態素、索引、接続コスト、文字分類、未知語規則および辞書情報を保持する。品詞名の原順序と各語 ID の品詞 ID 列・階層・表記も完全に復元できなければならない。重複する品詞列は不変な列として共有できるが、語の削除、語 ID の再割当て、表記の正規化および品詞情報の省略を認めない。

既に製品が使用しない `content.dict` と、同等な別表現へ移す `pos.dict` だけをシステム辞書 archive から除外する。他の entry は名前、順序および展開後の byte 列を保持し、生成時に再圧縮しない。`content.meta` を含む保持対象の変更には、本規定の変更審査を必要とする。

## 固定した生成元と manifest

生成元の module path、exact version、Go module の取得物識別、入力辞書の raw SHA-256 と byte 数は、生成物に対応する一つの機械可読 manifest へ記録する。取得物識別は既存の `go.mod` と `go.sum` の選択内容と照合し、任意のローカル入力へ既知版のラベルだけを付けてはならない。

manifest は形式 version、生成器の repository-relative path と source digest、生成時に実際に使用した Go 版、入力と出力の path・raw SHA-256・byte 数、保持／除外 entry の一覧、保持 entry の展開後 digest と byte 数、語数・品詞分類数・品詞名数、および上流の LICENSE／NOTICE の path と raw digest を持つ。version、件数、digest と具体的な版の選択値を SOT 本文へ重複定義しない。未知項目、重複項目、不正な path、未対応版および相互に矛盾する値を検証器が拒否する。

生成器と検証器は repository 内で管理する。同じ固定入力と生成器から、同じ生成物 byte 列を再現できなければならない。実行時刻、端末の絶対 path、利用者情報またはネットワーク応答を生成物へ混入させない。生成処理は一度固定・検証した同じ入力 byte 列を使い、出力の全照合が成功する前に採用済み集合を置き換えない。

生成時の Go 版は、その生成を実行した版の記録とする。`--check` は保存済みの生成記録を保持し、現在の検証環境で固定した Go 版で資産を再生成して、資産および当該記録以外の manifest の全 byte を照合する。保存された生成時の版と現在の CI の版の一致を要求しない。照合のために生成記録を現在の版へ書き換えない。

## 共有品詞表の形式

形式 version 1 の先頭は ASCII `JLMIPOS1` とし、後続の数値は little endian とする。

| 順序 | 内容 |
|---|---|
| 1 | 語数 `uint32`、品詞分類数 `uint16`、品詞名数 `uint16` |
| 2 | 原順序の各品詞名。UTF-8 byte 数 `uint16` とその byte 列 |
| 3 | 各品詞分類。階層数 `uint16` と、その数の品詞名 ID `uint16` |
| 4 | 原辞書の語 ID 順の品詞分類 ID `uint16` |

同一の品詞 ID 列は、語 ID 順に最初に現れた順序で一分類へまとめる。空の品詞名や階層の有無は上流値を保持し、意味を推定して補完しない。件数は各整数型で表せる範囲内とし、参照 ID は対象表の範囲内とする。必要な全件数は正でなければならない。末尾の余剰 byte、途中切断、不正な UTF-8、範囲外参照、形式の不一致および形態素表との語数不一致を拒否する。

## 読込みと製品境界

通常の製品 build は生成物を直接埋め込み、上流 IPA package の完全な archive を重ねて取り込まない。完全な辞書を一度展開してから縮約する経路を製品起動へ追加しない。上流の固定版は生成および同等性検証の参照として利用できる。

起動時には必要な archive entry の完全な集合、重複と未知 entry の不在、および共有品詞表の構造を検証する。検証済みシステム辞書と品詞列は不変に共有する。生成物全体の raw digest と由来の照合は生成・採用・配布の検証で行い、同じ検証を毎回の検索処理へ持ち込まない。

既知語の品詞は語 ID から同等な列を復元し、未知語と利用者登録語は既存の経路で取得する。製品が公開する surface、原文上の位置、登録語判定、品詞階層とその順序を保持し、共有列を変更可能な参照として公開しない。上流 tokenizer の token、feature または graph 出力を新しく公開する際には、この同等性境界を改めて確認する。

入力 query、結果または診断内容を本生成物や共有表へ追加しない。リクエストの一時状態および起動後の不変性は `SOT-ARCH-021` を定義元とする。

## 権利表示と配布

固定した上流の LICENSE、NOTICE および必要な帰属表示を原文のまま保持し、生成物を含むソースと公式配布物に付属させる。外部の権利条件が定めた原文を翻訳で置き換えない。プロジェクトが付ける由来や変更内容の説明は日本語とし、上流の原文と区別する。

公式のデスクトップ向け archive は、原文通知を `IPA-LICENSE` と `IPA-NOTICE.txt` の名前で直下へ添付し、実行ファイルは `SOT-DEL-010` の一つを維持する。通知は実行権限のない通常ファイルとし、一件につき 1 byte 以上 64 KiB 以下とする。配布検証は固定した実行ファイル名とこの二つの通知だけを受理し、不正 path、重複、不正な file type、未知 file、通知内容の欠落および検証対象 checkout の原文との byte 不一致を拒否する。通知の正本も上限内の通常ファイルとして読み、原文を取得できない場合に照合を省略しない。実行ファイルの展開は entry の順序に依存せず、検証済みの名前で選択する。

## 確認

中央品質ゲートの `ci` profile は、検証対象の同じ snapshot で `go run ./cmd/compact-ipa-generate --check` を実行し、採用済みの実資産と manifest の再生成一致を確認する。合成 fixture による生成器や decoder のテストだけで、この実資産の照合を代替しない。検証段階と資源方針は `SOT-ENG-027` に従う。

- 固定された入力取得物、manifest、生成器、全出力および権利表示の対応と再生成 byte 一致を確認する。
- 原辞書の全語 ID について品詞 ID 列と品詞名列を照合し、それ以外の全辞書部分および読込み後の構造が参照辞書と一致することを確認する。
- 既知語、未知語、利用者登録語、Unicode、反復語、位置の境界を含む入力で、製品が返す全 token 情報と検索結果が直前の採用実装に一致することを確認する。
- 合成生成物で形式、切断、余剰 byte、件数、参照、archive 構成の拒否と、公開 accessor による共有表の不変性を確認する。
- 同じ入力・実行条件で複数回比較し、検索速度を落とさず、保持メモリと初期化時の最大使用量を削減することを確認する。異なる最適化を同時に比較対象へ加えない。
- 製品 build の依存と埋込み対象に、生成用または参照用の完全な IPA archive が含まれないことを確認する。
- 検索品質の受入れと変更完了の検証は `SOT-ENG-024`、`SOT-ENG-020` および `SOT-ENG-027` に従う。静的な通知文の文言そのものを単体テストへ複製しない。

生成物を含む semantic source identity は `SOT-ENG-038` に従う。既存の一件・合計資源上限を緩和せず、過去に固定された評価成果物や registry を新しい生成物へ付け替えない。worker の版固定と履歴は `SOT-ENG-049` を定義元とする。
