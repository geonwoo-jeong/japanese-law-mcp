# SOT-ENG-019: 静的解析とコーディングスタイル

- 状態: 有効

## 規定

Go コードのコーディングスタイルと機械的に判定できる品質制約は、個人ごとの慣習ではなく、SOT を上位の根拠とするバージョン固定済みのフォーマッター、リンターおよび静的解析によって統一する。

## 適用

- Go コードの整形には `gofmt` を使用し、別の整形規則を重ねない。
- 汎用リンターは、暗黙の既定集合を使用せず、リポジトリの設定で有効にする項目を明示する。
- プロジェクト固有の制約は `go/analysis` による解析器で検証する。解析器は既存の有効な SOT を根拠とし、診断に該当する SOT ID を含め、許可例と違反例のテストを持つ。
- リンターまたは解析器の抑制は、対象と検査名を最小範囲に限定し、抑制記述に日本語の理由と根拠となる SOT ID を記載する。検査全体またはファイル全体の無条件な無効化は行わない。
- 生成物など一括除外が必要な対象は、中央の設定または共通解析処理に識別条件と理由を記載し、ソースコード内へ分散させない。
- ツールと規則の更新は、固定バージョン、設定、既存コードへの影響および検証結果を同じ変更で一致させる。
- 人または AI が生成したコードを区別せず同じ検証へ通す。確定的に再実行できない AI レビューは補助として扱い、必須ゲートの代わりにしない。

設定ファイルと解析器はこの規定の派生成果物であり、SOT と競合する独自のコーディング規則を定義しない。

## 確認

有効なリンターの集合、ツールの固定バージョン、抑制理由およびプロジェクト固有解析器のテストを確認し、同じソース状態に対してローカルと CI が同じ結果を返すことを確認する。
