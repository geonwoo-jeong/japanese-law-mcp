# SOT-ENG-021: Git フックによる段階的検証

- 状態: 廃止
- 後継: [SOT-ENG-027: 省資源の段階的検証](27-resource-aware-verification-stages.md)

## 規定

コミット前、プッシュ前および CI の検証は、検査するソース状態と外部状態への依存を段階ごとに明示し、最終的な変更完了の判定を CI に集約する。

## 有効化

- Git フックはリポジトリで管理する `.githooks` を使用し、利用者が `.githooks/manage install` を実行して、当該リポジトリのローカルな `core.hooksPath` を `.githooks` に設定する。
- インストール処理は大域の Git 設定を変更せず、当該リポジトリに別のローカル `core.hooksPath` が設定済みの場合は上書きしない。
- `.githooks/manage` は、Git common directory とその配下の専用 `GOCACHE` および `GOLANGCI_LINT_CACHE` が symlink ではない実ディレクトリであり、POSIX の group/other write bit を持たないことを Go の初回起動前に確認する。`install` と `uninstall` では不足する専用キャッシュだけを安全な権限で作成し、安全性を確認できないキャッシュや ambient の Go build cache へ処理を緩和しない。
- Go module cache は、モジュールごとの複製を避けるため標準の content-addressed cache を再利用する。`install` は固定済みバージョンを `go.sum` と `GOSUMDB` で検証して必要なモジュールを準備し、`pre-commit` と `pre-push` は `GOPROXY=off` で実行する。必要なモジュールが cache にない場合は検査を失敗させ、ネットワーク取得または検査省略へ緩和しない。
- `.githooks/manage check` は、ローカル設定、管理 entrypoint とフックの本文、実行可能性、および専用キャッシュを確認する。
- `.githooks/manage uninstall` は、当該リポジトリのローカル `core.hooksPath` が `.githooks` を指す場合に限り、その設定を解除する。追跡対象のフックファイルと大域設定は削除しない。
- clone 後はインストールを明示的に行う。フックを導入できない環境でも CI の必須検証は省略しない。

## コミット前

- `pre-commit` は作業ツリーではなく、コミット予定の Git index を一時領域へ展開したスナップショットを検査する。部分的にステージした変更、初回コミットおよび削除を含め、未ステージの内容を結果へ混入させない。
- 検査中に index または作業ツリーを書き換えず、path 依存の解析結果を持つリンターキャッシュを含む一時領域を終了時に破棄する。
- 対話入力、ネットワークおよび現在の外部データベースを必要としない、高速な `pre-commit` プロファイルだけを実行する。
- 検査が失敗した場合はコミットを中止する。

## プッシュ前

- `pre-push` は標準入力で通知された ref 更新を解釈し、削除以外の更新が指す重複のない各コミット tip を一時領域へ展開したスナップショットとして検査する。作業ツリーの状態を結果へ混入させない。
- 各送信範囲を秘密情報検査へ渡す。履歴のない新規 ref、または通知された remote tip の object をローカルで取得できない更新では、送信する tip から到達可能な全履歴を検査し、取得できた範囲より狭い検査を成功として扱わない。
- `SOT-ENG-020` のゲートのうち、現在の外部脆弱性データベースに依存しない決定的な全検査を `pre-push` プロファイルで実行し、一つでも失敗した場合はプッシュを中止する。
- 削除のみの更新は検査対象の tip を持たないため、スナップショット検査を行わない。

## CI

- CI は clean checkout した対象コミットに対して `ci` プロファイルを実行し、変更完了を判定する権威あるゲートとする。
- `SOT-ENG-018` の適用変更または初回導入では、変更側が上書きできない event metadata から `SOT-ENG-020` が定める base ref を渡して `provider-onboarding-fit` を先に実行し、その成功後に `ci` プロファイルを実行する。
- `ci` プロファイルは `pre-push` の検査に加え、製品コードと固定済み検証ツールを現在の脆弱性データベースで検査し、テスト用パッケージから到達可能な脆弱性も対象にする。また、取得した Git 全履歴を秘密情報検査の対象にする。
- 脆弱性データベース、取得対象の全履歴または検査ツールへ到達できない場合は、検査成功として扱わない。

Git の `--no-verify` によってローカルフックを迂回できるため、フックの成功を `SOT-ENG-020` の完了判定または CI の代わりにしない。CI はローカルフックの実行有無にかかわらず同じ対象を再検証する。

## 確認

一時 Git リポジトリを使うテストで、index と作業ツリーの分離、部分ステージ、初回コミット、削除、複数 ref、重複 tip、不正な入力、一時領域の破棄、およびローカル `core.hooksPath` の保全を確認する。CI の clean checkout から `SOT-ENG-020` の中央の標準コマンドが成功し、`SOT-ENG-018` の適用変更または初回導入では同 SOT が定める先行 command も成功し、外部検査の失敗が成功へ緩和されないことを確認する。

## 廃止理由

ローカルの `pre-push` へ全テスト、全体カバレッジ、静的解析および
module 検査を重複して課す方式は、利用者の端末で過大な CPU、メモリおよび
電力を消費した。ローカルを変更範囲に限定した早期検査とし、権威ある全検査を
CI に一回だけ集約する `SOT-ENG-027` へ置き換えた。
