# SOT-ARCH-018: 拡張パック単位の正規化境界

- 状態: 有効

## 規定

情報源データは、意味が一致する最小の共通メタデータと能力別の型付きモデルへ変換し、法令コアまたは異なる拡張パックの識別子、日付、状態および本文を同じ共通キーへ平坦化しない。

## 共通化する範囲

次の項目だけをプロバイダー横断かつ能力群横断の共通語彙とする。

- `InformationSource`
- `SourceResourceKey`
- `SourceResourceRef`
- `Provenance`
- `ProviderCapability`
- `SourcePage`
- 共通の情報源エラー分類

法令能力の意味と項目は、安定提供される e-Gov 法令 API Version 2 の XML、法令識別子およびリビジョンを基準とする。e-Gov 法令 API Version 1 または別の法令情報源は、同じ意味を確認できる項目だけを法令モデルへ対応させる。

## 能力別に保持する範囲

同じ文字列表現へ変換できる項目であっても、次の意味を能力別モデルに保持する。

| 能力群 | 識別子 | 日付 | 状態 | 本文または公表物 |
|---|---|---|---|---|
| 法令 | 法令 ID、法令番号、リビジョン | 公布日、施行日、更新対象日 | 法令種別、改正と施行の状態 | 構造化された法令本文、条文および添付資料 |
| 裁判例 | 事件番号、裁判例の情報源識別子 | 裁判年月日 | 裁判所、事件種別および公表範囲 | 裁判本文、判示事項、裁判要旨および PDF |
| 国会会議録 | 会議録 ID、会議 ID、発言 ID | 開会日、会議日および発言に付随する日時 | 国会回次、院、会議および発言の位置 | 会議録、議事および発言本文 |
| 議案 | 国会回次、議案種別、議案番号および情報源識別子 | 提出日、付託日、議決日および公布日 | 提出、審査、議決、成立その他の審議経過 | 議案本文、要旨、審議経過、HTML および PDF |
| 行政解釈資料 | 通達番号、通知番号その他の公表識別子 | 発出日、改正日および適用日 | 文書種別、所管および適用範囲 | 通達、通知、指針、回答、HTML および PDF |
| 行政裁決 | 裁決番号、事件番号その他の公表識別子 | 裁決日および公表日 | 裁決機関、争点および公表範囲 | 裁決本文、裁決要旨、HTML および PDF |

完全な暦日を情報源で確認できる場合は、公開 JSON で `YYYY-MM-DD` を使用できる。ただし、公布日、施行日、裁判年月日、会議日、提出日、発出日および裁決日という意味を別の項目名で保持する。年月だけ、年だけ、期間または不明な日付を、月初、月末その他の推測した完全な暦日へ変換しない。日付の精度と外部表現は各能力別 SOT で定義する。

`official` と `supplementary` の権威区分は情報源の性質を示すものであり、法令、裁判例、行政解釈資料または行政裁決の法的効果が同じであることを示さない。

## 禁止する形

- 異なる能力群の識別子を一つの `id` だけへ縮約すること
- 意味が異なる日付、状態または本文を一つの `date`、`status` または `content` へ縮約すること
- 共通モデルへ対応できない値を、無制限の `map[string]any`、名前空間のない `extensions` または意味を定義しない `raw` へ格納すること
- 複数の能力群を横断する結果を、情報種別を識別できない一つの行形式へ結合すること

複数の能力群を一度に扱う利用目的が採用された場合は、能力別の結果を分けるか、情報種別を明示する型付き union として返し、各結果の `Provenance` と固有の意味を保持する。

## 確認

変換前後で公式識別子、日付の意味と精度、文書種別、権威区分および公表範囲を失っておらず、確認できない値を補完していないことを能力別の契約テストで確認する。
