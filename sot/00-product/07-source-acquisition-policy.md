# SOT-PROD-007: 情報源取得方式の選択

- 状態: 有効

## 規定

情報源の取得方式は、情報の権威性、意味の一致、公式仕様の明確さ、構造の安定性および検証可能性を評価し、必要な情報を最も損失なく取得できる方式を選ぶ。

## 選択基準

同じ情報を取得できる場合は、文書化された公式 API、公式の構造化配布ファイル、公式 HTML または PDF、補助的な情報源の順に優先して評価する。

公式 HTML または PDF の自動取得は、同じ意味と範囲を持つ公式 API または構造化配布物がなく、現在の利用条件を確認でき、原文 URL、取得範囲、文字コード、構造変更の検出方法および負荷を抑える取得方法を定義できる場合だけ採用する。

補助的な情報源は、一次情報源との差異、採用目的および適用範囲を情報源ごとの SOT に記載する。公的機関のサイトに掲載されていることと、文書の法的効力または網羅性を同一視しない。

第三者のクライアント実装、未公開エンドポイントまたは観測した挙動だけを外部仕様の定義元にしない。認証、呼び出し制限、再利用条件または更新頻度を公式資料で確認できない場合は、値を推測せず未確認として扱う。

情報源ごとのインターフェース SOT は、利用条件、再利用条件、User-Agent または連絡先の要件、呼び出し間隔、同時実行数、`Retry-After`、backoff および日次上限について、公式資料で確認できた内容と未確認の内容を区別して記載する。数値を確認できない場合は、公式条件に反しない保守的な固定間隔と同時実行上限を定義できることを採用条件とする。

固定間隔は、一つのリクエストが複数の外部呼び出しを順に行う場合の呼び出し間隔として定義する。同時実行数は現在実行中の外部呼び出しだけを数え、呼び出しの完了時にその状態を破棄する。過去の呼び出し時刻、利用主体別の回数または日次使用量をリクエスト間で保存してはならない。

公式条件が、日次上限、時間窓ごとの回数またはリクエストをまたぐ最小間隔の強制を要求する場合は、開発原則 6 に反する利用履歴を保存せずに遵守する方法を提供方式の SOT で先に採用する。その方法がない提供方式では、該当情報源を有効にしない。

## 確認

情報源ごとのインターフェース SOT から、提供主体、公式仕様または公式掲載ページ、確認日、取得方式、利用条件および構造変更の検証方法へ到達できることを確認する。
