# SOT-IF-016: 情報源の継続取得

- 状態: 有効

## 規定

新しい能力別の一覧および検索インターフェースは、初回の `limit` と、同じ条件の続きを取得するための不透明な `continuationToken` を共通の継続取得契約とする。

## 入力

| 項目 | 型 | 必須 | 意味 |
|---|---|---:|---|
| `limit` | integer | いいえ | 今回返す上限。能力別 SOT が既定値と最大値を定義する |
| `continuationToken` | string | いいえ | 直前の結果が返した次の取得位置 |

`continuationToken` を指定した場合は、初回と同じ検索条件および `limit` を使用する。条件が一致しない場合、期限切れの場合または改変を検出した場合は `invalid_argument` とする。

## トークン

トークンはサーバー側にセッションを保存せず検証できる形とし、署名または AEAD によって改変を検出する。プロバイダー ID、能力 ID、能力のメジャーバージョン、外部情報源の取得位置、発行時刻、有効期限および検索条件の秘密鍵付き HMAC または暗号化した値だけを含める。

検索語の原文、第三者が候補入力と照合できる鍵なしの hash、認証情報、取得した情報、利用主体、外部レスポンスまたは診断値を含めない。利用者がトークン内部の値を組み立て、変更または解釈する契約にしない。

能力別 SOT はトークンの有効期限上限を定義する。期限切れのトークンを受け入れず、署名鍵または暗号鍵をトークン、ログ、エラーまたは診断へ含めない。

offset、`startRecord`、`NEXT_KEY`、`divideNumber`、日付内の取得位置またはプロバイダー別の継続値は、各アダプターがトークンとの間で変換する。初回条件そのものに意味がある日付、統計の次元または地理タイルは継続位置へ置き換えない。

既存の MCP ツールが定義する `offset` と `nextOffset` は、公開インターフェースを別の SOT で変更するまで維持する。
