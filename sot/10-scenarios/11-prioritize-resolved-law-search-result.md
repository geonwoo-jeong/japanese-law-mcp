# SOT-SCN-011: 解決済み法令を検索結果で優先する

- 状態: 有効

## 規定

利用者は、正式名称、出典付き別名、法令名を一つ含む自然文または一意な
軽微誤記で `search_laws` を実行した場合、原検索を失わず、同じ page に
含まれる解決済み法令を先頭で確認できる。

本規定は `SOT-SCN-008` を置き換える。

## 開始条件

利用者が `search_laws` に有効な検索語を渡している。解決済み法令の有無は、
情報源を呼び出す前に provider 非依存の法令名辞書と日本語解析から判定する。

## 基本フロー

1. システムは、`SOT-ARCH-030` の provider 非依存規則により、
   検索語から一つの公式法令 ID を安全に解決できるか判定する。
2. システムは、解決の成否にかかわらず、検証済み原文を変更せず選択済みの
   法令検索 provider で最初に検索する。
3. 原検索が正常な非空結果で、解決済み法令が現在の page に含まれる場合は、
   その法令を page の先頭へ安定的に移す。対象外 item の相対順、総件数、
   次の取得位置および出典は変更しない。
4. 原検索の `totalCount` が零で、法令を一つへ解決できた場合だけ、辞書で
   確認した正式名称を使い、同じ provider、日付、件数および取得位置で
   確認検索を一回行う。
5. 確認検索が正常結果を返した場合も、同じ page 内の安定優先を適用する。
   原検索と確認検索の item、総件数または取得位置は結合しない。
6. 法令を一つへ解決できない場合、または確認検索も正常な空結果の場合は、
   原検索の空結果を返す。
7. 原検索または確認検索が error を返した場合は、別の検索語、別 page または
   別 provider で隠さず、その error を返す。

## 完了条件

返された各 item は公式情報源が実際に返した `LawSummary` であり、解決済み
法令の優先は現在の一 page の順序だけに影響する。

facade が provider port へ渡す論理検索 operation は、原検索と正常な空結果後の
確認検索を合わせて二回以下である。一つの operation 内の HTTP 自動再試行は
`SOT-IF-004` に従い、論理検索回数へ加算しない。
対象 item が現在の page にない場合も、別 page の取得または item の生成を
行わない。

## 確認

正式名称、公式略称、補足別名、互換表記、自然文内の一法令名および一意な
挿入・削除・置換・転置を fixture にする。解決済み法令が原検索または
確認検索の三件目にある場合は先頭へ移し、ほかの item の相対順、件数、
次位置および出典を保持することを確認する。

複数法令を含む自然文、衝突する略称、同率誤記候補、短い語、対象法令が
現在の page にない結果、および `offset` より前にだけ対象法令がある結果では、
provider 順と page 境界を変更しないことを確認する。
