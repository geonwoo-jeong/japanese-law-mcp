# 共通プロバイダーインターフェース評価

この文書は、共通プロバイダーインターフェースの設計レビューと改善の履歴を記録する。採用する規定の定義元は [SOT](../sot/00-index.md) とし、この文書を仕様の定義元にはしない。

## 評価方法

適用対象を十項目に分け、各項目を十点満点で評価する。

| 点数 | 判定基準 |
|---:|---|
| `10` | 定義、失敗経路、検証および将来の変更境界が閉じており、独立レビューで改善点がない |
| `9` 以上 | `P0` と `P1` がなく、実装者が追加の意味判断をせずに実装と検証を開始できる |
| `8` 以上 | `P0` はないが、実装前に解消すべき一つの `P1` または同等の暗黙条件がある |
| `6` 以上 | 複数の `P1`、未定義の公開契約または機械検証できない条件がある |
| `5` 以下 | 有効な規定同士の矛盾、または仕様どおりの実装を開始できない阻害条件がある |

完了条件は、十項目のすべてが二つ以上の独立レビューで `9.0` 以上となり、`P0` と `P1` が残っていないことである。平均点による相殺は行わない。

## 評価の実行前提

この設計の実行対象は、利用者のローカル環境で MCP クライアントが起動する単体の実行ファイルとする。

外部から継続監視するサービスではないため、稼働率の集計、運用障害の検知、`liveness`、`readiness`、常時監視および復旧 runbook は評価対象に含めない。ローカルプロセスの起動失敗と設定不備は終了コードと標準エラー、処理中に発生した外部情報源の障害は各 MCP リクエストの公開エラー、一時的な追加調査は明示的に有効化する非保持の診断で扱う。

## 評価項目

1. 製品範囲と意味の境界
2. 共通モデル、識別子および出典
3. capability と API 契約
4. プロバイダーの分離と変更耐性
5. 継続取得、選択および組合せ
6. エラー契約
7. セキュリティと秘密情報
8. 資源上限、性能および拡張性
9. 設定、起動時検証およびローカル実行の一時性
10. テスト、適合性および変更検出

## 第 0 回

独立した五つの敵対的レビューで確認した、改善前の基準点である。

| 項目 | 点数 | 主な減点理由 |
|---|---:|---|
| 製品範囲と意味の境界 | `8.0` | 未採用の非法令 capability 候補が、採用済みの共通語彙に見える |
| 共通モデル、識別子および出典 | `7.5` | URL の path だけでは query で区別する資源が衝突する |
| capability と API 契約 | `5.0` | e-Gov の既存機能にも登録可能な capability SOT がない |
| プロバイダーの分離と変更耐性 | `7.5` | 検証日と parser contract の変更境界が粗い |
| 継続取得、選択および組合せ | `6.0` | token が limit、adapter 版、設定 scope および snapshot に束縛されない |
| エラー契約 | `6.5` | 情報源エラーを公開する後継契約がない |
| セキュリティと秘密情報 | `7.0` | ambient proxy、非 loopback 公開および token 検証条件に不足がある |
| 資源上限、性能および拡張性 | `6.0` | 外部応答と解析の数値上限がなく、試験値を決められない |
| 設定、起動時検証およびローカル実行の一時性 | `5.0` | 利用履歴を禁止しながら利用主体別の分間回数を要求している |
| テスト、適合性および変更検出 | `6.5` | provider/capability ごとの必須試験を機械判定する表がない |

## 第 1 回

共通 capability、provider descriptor、route、継続トークン、公開エラー、資源予算、conformance matrix、onboarding gate および local-only delivery を追加した後の敵対的レビューである。

途中レビューの各項目における最低点は次のとおりだった。

| 項目 | 最低点 | 発見した主な `P1` |
|---|---:|---|
| 製品範囲と意味の境界 | `10` | なし |
| 共通モデル、識別子および出典 | `9` | なし |
| capability と API 契約 | `8` | `search_laws` の `nextOffset` 生成規則が公開 facade と mapping で一致しない |
| プロバイダーの分離と変更耐性 | `9` | なし |
| 継続取得、選択および組合せ | `8` | `next_offset` が返却件数と一致せず item を飛ばせる |
| エラー契約 | `9` | なし |
| セキュリティと秘密情報 | `9` | なし |
| 資源上限、性能および拡張性 | `9` | なし |
| 設定、起動時検証およびローカル実行の一時性 | `9` | なし |
| テスト、適合性および変更検出 | `8` | ページ不変条件の fixture が conformance gate の必須 case に接続されていない |

レビュー中に次を修正した。

- `SOT-IF-009`、`SOT-IF-010` および `SOT-IF-028` で、件数、配列長、総件数、`null`、欠落、前進性および `next_offset == offset + returnedCount` を固定した。
- `SOT-IF-030` と `SOT-IF-033` で、公開 `nextOffset` を同じ検証済み取得位置へ固定した。
- `SOT-ENG-017` に `page-invariants` を追加し、`supportsContinuation: true`、`law.search@1` および `law.content.search@1` で `n/a` にできない必須 case とした。
- `SOT-IF-009`、`SOT-IF-022` および `SOT-IF-030` で、既存 facade の任意 `offset` と `asOf` 省略を、内部 capability の署名済み continuation と snapshot へ lossless に変換しない境界を明示した。
- `SOT-IF-033` で e-Gov 検索式の決定的な受理構文を定義し、`SOT-ENG-016` で artifact ごとの byte、構造単位および深さの計測方法を固定した。

この回の `P1` はすべて解消してから最終レビューを行った。
